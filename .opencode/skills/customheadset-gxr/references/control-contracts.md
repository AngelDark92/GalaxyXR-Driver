# Numeric control contracts

- Every numeric setting declares one spec in `GalaxyXRDriverGUI/src-lit/domain/control-specs.ts`. Seven constraint kinds: closed set, sentinel, capability bound, context gate, cross-field ordering, precision, degenerate guard. "None" is a declared answer, not an omission. Pages render through `numberControl` / `choiceControl` / `sliderControl`; a hand-written `<app-number min max step>` is a defect.
- Tile width is capability-bounded, not a free integer. The session probe requires `tile * 4 <= the selected codec's NVENC height max` and refuses instead of lowering the request (`NvencTap.cpp:2087-2113`). H.264 is capped at 1024; HEVC and AV1 at 2048 (`Config.h:355`). The negotiated classes are 1024 and 1536. A stored value above the codec cap is displayed and flagged, never rewritten.
- Codec changes the meaning, not only the bound. Split mode is inert on H.264. Preset automatic resolves to P2 on H.264 and P7/P5/P4 by engine count elsewhere. VUI tags are written for HEVC/H.264 only. The QP-map block grid is 16/32/64 px for H.264/HEVC/AV1 (`NvencTap.cpp:106-150,1108-1130`). Max QP is codec-specific; do not hardcode 51.
- Sentinels are values, not blanks: `0` = follow Max Bitrate, preserve the caller's VBV, follow the pacer bandwidth, automatic preset, disabled max QP; `-1` = leave upstream / autoselect; `15` = split disabled; `0` = off for most tuning scalars. Never render them as `0` without the word.
- Cross-field rules the native layer enforces or assumes: `minQp <= maxQp` when `maxQp > 0`; automatic H.264 GOP/IDR needs a nonzero frame rate; VUI full range must agree with post-pack limited range; annulus `rMin < rMax`; shadow floor `<` knee; tuner bands `first < last`.
- A slider may not be the only control where the native contract is wider than the slider band. Fluent clamps the thumb; the paired number keeps the stored value visible. A slider is guidance, never a gate (owner policy: user-entered settings are authoritative).
- Only three coercions are sanctioned, each at a boundary, and each must display the effective value: render dimensions rejected by `ConfigLoader.cpp:418-424`; OFXR `maxLogMb` normalized at the IPC (`domain/ofxr.ts:46-59`); UI scale normalized in the GUI (`ui/ui-scale.ts:22-28`). Everything else keeps the entered value and fails visibly.
- Step is an input increment, not validity. Exceptions are integer contracts, and values the consumer quantizes (tuner bands round to 3 decimals; bitrate-curve points quantize to the request domain).
- A value can be valid and still inert. `appliesWhen` / `requires` in the spec resolve against the live control context and render an orange "saved, not applied" note (Force CBR, H.264, AV1 VUI, grip compensation, adaptive lead, gaze assist, derive mode, fast estimator, Soft duplicates, OFXR logging). They never change or hide the stored value.
- Adding or changing a numeric setting: spec first, then the page row, then XLIFF, then `npm test` (the coverage ratchet fails a new hand-written numeric control), then the portable build gate.
