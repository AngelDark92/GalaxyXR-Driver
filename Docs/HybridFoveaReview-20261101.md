## Remaining defects

1. **P2 — stale settings can overwrite a newer publication.** [HybridConfigGlue.cpp:110](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/GalaxyXR-Driver/GalaxyXRDriver/src/Driver/HybridConfigGlue.cpp:110) locks the apply sequence only after taking settings/NVENC snapshots and publishing the enabled hint/hook state. A delayed render-thread Off snapshot can run after a newer watcher-thread On apply, leaving the producer Off and hint false; subsequent Present skips reapplication. Serialize snapshot→hint/hook→Configure together, or discard stale configuration generations. Test with a barrier holding an old Off apply while a newer On publication completes.

2. **P2 — disabling Tap on an existing tap-created encoder also disables hybrid.** [NvencTap.cpp:1784](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/GalaxyXR-Driver/GalaxyXRDriver/src/Driver/NvencTap.cpp:1784) returns before hybrid submission accounting when Tap is off; lock at2134 likewise returns before hybrid wrapping. The separate hybrid-only wrapper does not replace callbacks already held by this session. Keep hybrid submit/lock handling independent of encoder-override enable, preserving required ABI translation and ordinary passthrough. Test Tap On→Off on the same encoder with hybrid still selected; require continued joins or an explicit unsupported-session rejection.

3. **P2 — envelope codec can describe a setting instead of the live encoder.** [HybridConfigGlue.cpp:73](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/GalaxyXR-Driver/GalaxyXRDriver/src/Driver/HybridConfigGlue.cpp:73) chooses runningBase from the current tap snapshot. A hybrid-only HEVC session created with Tap off does not intercept initialization/reconfiguration (`NvencTap.cpp:2060`); enabling Tap with AV1 saved can therefore make `HybridProducer.cpp:801` label unchanged HEVC bytes as AV1. Observe accepted encoder initialization/reconfiguration without modifying it, retain actual codec facts per session and use them for admission/envelopes. Test this transition without creating a new encoder; never silently change either user selection to conceal the mismatch.

4. **P2 — GPU output allocation can become permanently incomplete after failure.** [AstcGpuEncoder.cpp:723](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/GalaxyXR-Driver/GalaxyXRDriver/src/Driver/AstcGpuEncoder.cpp:723) retires output/UAV/staging on growth without clearing old capacity. If the new output buffer succeeds but UAV/staging creation fails, a later smaller batch passes the cache check with missing resources. Build replacements locally and commit only on complete success, or clear capacity and require all three handles before reuse. Inject UAV/staging failure during growth, then verify smaller-batch recovery. Source-confirmed; no allocation-failure runtime was injected.

5. **P2 — matching a later DXGI adapter leaks the earlier candidate.** [AstcGpuEncoder.cpp:554](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/GalaxyXR-Driver/GalaxyXRDriver/src/Driver/AstcGpuEncoder.cpp:554) can choose the requested LUID after retaining an earlier `best` adapter. Only `chosen` is released at592; unused `best` survives repeated off/on cycles on that topology. Release the unused candidate or use COM RAII. Test reference ownership when the match is not the first enumerated hardware adapter.

The next three defects affect **explicit CPU bench decoding**, not the default demux-only mode. They must be fixed before relying on those tests or reusing this session machinery for GPU composition.

6. **P2 — worker coalescing can lose the only epoch-reset envelope.** [hybrid_session.cpp:318](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/steamlink-patches/extensions/hybrid-codec/src/hybrid_session.cpp:318) replaces pending jobs before epoch admission, which occurs at344. An old epoch decoding → new-epoch Reset queued → next new-epoch frame queued can discard Reset and leave all subsequent frames rejected as `epoch_mismatch`. Host sends Reset only on the epoch's first envelope (`HybridProducer.cpp:783`). Admit/preserve epoch-control state before newest-frame coalescing. Test this exact blocked-worker schedule.

7. **P2 — worker generation checks bracket admission incorrectly.** [hybrid_session.cpp:344](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/steamlink-patches/extensions/hybrid-codec/src/hybrid_session.cpp:344) admits a job before checking whether it is obsolete. A surviving job can repin a retired epoch after explicit Reset. Conversely, legitimate epoch admission increments `generation_` but the job keeps its enqueue generation, so CommitFrame at381 rejects the first decoded frame of the new epoch. Reject obsolete work before admission and capture the resulting generation after successful admission. **Executed witness:** old worker frame available; next valid reset frame consumed; one second later no new layer and status `reset`.

8. **P2 — a degraded reset leaves the prior epoch's layer cached.** [hybrid_session.cpp:454](D:/Angelo/Desktop/SteamLink-GalaxyXR-Windows-Toolkit-FULL/steamlink-patches/extensions/hybrid-codec/src/hybrid_session.cpp:454) returns before epoch admission/cache invalidation when no fovea is present. **Executed witness:** decoded frame1 → valid new-epoch Reset+Degraded envelope → `TakeLatest` still returns frame1, status `strip_only`. Process validated reset/control state before the no-fovea return. Add this regression and verify the next new-epoch frame is admitted.

## Open requirements / evidence limits

- Readiness acknowledgement, headset ASTC upload/sampling/composition, colour/capacity proof and worn/thermal validation remain open as the overview states. The implementation cannot yet display the custom fovea. PyroWave GPU remains unimplemented; its labelled CPU mode is not an upstream-compatible GPU substitute.
- The earlier strict no-fallback requirement remains different from current behaviour: late/failed enhancement intentionally produces base-only video. Counters and documentation make it visible, but do not make the selected enhancement present. Resolve the recovery/admission contract explicitly before claiming selected-mode delivery; retain correct buffer ownership and do not fake codec success. This is separate from keeping base video resilient to packet loss.
- Scene-frame equality is enforced, but associating NVENC submissions with the latest announced Present ID is still an unproven runtime assumption. Obtain source/submission/output/display correlation; the fixture cannot establish it. Base adaptive-rate headroom also remains unowned unless separately proved; a warning or Force CBR suggestion is not a transport-budget guarantee.
- Shared GPU capture now works in the tested route. Automatic `cpu_staging` capture fallback still blocks the Present thread and needs an explicit admitted policy/deadline measurement. The ASTC timing below is one warmed small synthetic call, not real-resolution/contention p95/p99 or headset cost.
- Independent ASTC agreement applies to the tested corpus; current custom outputs remain 8-bit/lossy. No lossless/10-bit-core or imperceptible-periphery claim follows. PyroWave's global bitplane budget reduction also lacks a protected-core reconstruction-error floor; add one if near-lossless foveal quality is mandatory and reject infeasible budgets rather than relying on byte compliance alone.
- Client README still has stale claims: its Limits section says precision10 is accepted, while the full parser rejects it (`gxh1_parse.cpp:171`); its coverage description says16-pixel grid while validation is exact; its Integration paragraph omits the wrapper's pre-helper magic check. Clarify full parser/bench guarantees versus production's limited `QuickHeader` demux validation and host-only timing.
